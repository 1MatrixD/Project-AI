# Проекты ИИ

Self-hosted система «второй мозг проекта»: детальная карта знаний кодовой базы в Neo4j,
чат с ИИ (Claude Code headless), канбан задач, обработка материалов (созвоны, ТЗ,
документы) и генерация плагинов Claude Code для каждого проекта.

## Что умеет

- **Создание проекта** — указываешь каталог с кодом (кнопка «Обзор…» открывает
  системный диалог Windows), в фоне запускается анализ: структура, стек, ИИ-разбор
  каждого файла (роль, сущности, связи) → граф знаний Neo4j.
- **Дубликат проекта** — копия со всей картой знаний: файлы приезжают уже
  проанализированными, поэтому ИИ-разбор не запускается заново. Копия независима
  (свои строки в БД, свой подграф Neo4j, свои вектора) — удаление оригинала её не
  задевает. Каталог с кодом остаётся общим, наблюдение за ним у копии выключено.
- **Мультирепо** — к проекту можно добавить несколько каталогов (например, отдельные
  репозитории бэкенда и фронтенда): общий индекс, граф, поиск и канбан; файлы
  дополнительных каталогов ходят с префиксом «алиас/».
- **Гибридный поиск** — полнотекстовый по графу + семантический по эмбеддингам
  (Qdrant, локальная модель — без API-затрат): ИИ находит нужное, даже если
  в запросе другие слова, чем в коде и выжимках.
- **Обновления** — инкрементальный скан показывает, что изменилось (added/modified/deleted),
  переанализируются только изменённые файлы. Кнопка «Перепроверить всё» — полный пере-анализ.
- **Материалы** — загрузка записей созвонов (mp4/m4a/mp3 → локальный Whisper на GPU),
  ТЗ и документов (pdf/docx/xlsx/md/txt → извлечение текста). Из материалов ИИ делает
  выжимку и **извлекает задачи в канбан**.
- **Канбан** — Запланировано / В работе / Ревью / Готово, drag&drop. Задачу можно ставить
  как угодно длинно — короткая подпись остаётся на карточке, полный текст уходит в описание
  и целиком доходит до проработки. Готовую задачу (описание, шаги, развилки, что заденет,
  файлы) копируешь одной кнопкой и вставляешь в Claude Code. ИИ управляет доской через
  MCP-инструменты: создаёт задачи, улучшает описания, помечает выполненное с отчётом.
- **Планировщик** — крупная задача (например, с созвона) декомпозируется: RLM-исследование
  кодовой базы → общий план → подзадачи в канбане с зависимостями «что за чем делать».
- **Наблюдение за каталогом** — включаешь галку, и правки в коде сами запускают
  инкрементальное обновление индекса (watchdog с дебаунсом).
- **ИИ-проверка «что уже сделано»** — по каждой открытой задаче ИИ ищет реализацию
  в кодовой базе и помечает выполненные с отчётом и ссылками на файлы.
- **Чат с ИИ** — стриминг, выбор модели (**Opus 5 по умолчанию** / Sonnet / Haiku) и глубины
  размышлений. ИИ видит карту знаний, файлы, материалы, канбан (через MCP) и использует
  **RLM** (Recursive Language Models, MIT) для работы с большими кодовыми базами.
- **Суб-агент актуализации** — после `task_done`/`log_work` фоновый процесс пересканирует
  изменения и обновляет карту знаний.
- **Плагин Claude Code на проект** — MCP-сервер + скиллы (архитектура, бизнес-логика,
  рабочий процесс). Ставится кнопкой **только в свой проект** (запись в
  `<каталог проекта>/.claude/settings.local.json`), поэтому в остальных репозиториях
  его не видно; глобальная установка через маркетплейс осталась как вариант.

## Запуск

Требуется: Docker Desktop, Python 3.13 (`py`), Node.js 20+, установленный и авторизованный
[Claude Code CLI](https://code.claude.com/docs/en/cli-reference).

Одной командой (поднимет docker-инфраструктуру, при первом запуске поставит зависимости,
откроет бэкенд и фронтенд в отдельных окнах и запустит браузер):

```powershell
.\start.ps1
```

Либо вручную:

```bash
# 1. Инфраструктура (Postgres 5432, Neo4j 7474/7687, Qdrant 6333)
docker compose up -d

# 2. Бэкенд (порт 8010)
cd backend
py -3.13 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8010

# 3. Фронтенд (порт 3010)
cd frontend
npm install
npm run dev          # порт 3010 зашит в скрипт
```

Открыть http://localhost:3010. Конфигурация — в `.env` (см. `.env.example`).

## Тесты

```bash
cd backend
.venv\Scripts\python -m pytest -q
```

37 интеграционных тестов гоняют весь пайплайн (индексация → граф → векторный поиск →
мультирепо → задачи → планировщик → чат → материалы → git-импорт → SSE/отмена →
watchdog → alembic-миграции) на фейковом claude-бинаре и фейковом эмбеддере — без
затрат на API. Нужны запущенные Postgres, Neo4j и Qdrant из docker compose.

## Миграции

Схема Postgres описана моделями в `backend/app/models.py`, ревизии лежат
в `backend/alembic/versions/`. При старте бэкенда миграции накатываются сами
(`app/db.py` → `alembic upgrade head`), так что после `git pull` достаточно
перезапустить сервер. Установки, сделанные до перехода на alembic, помечаются
базовой ревизией автоматически — руками ничего штамповать не нужно.

По той же причине после `docker compose down -v` (снос тома вместе с данными) базу
нужно поднять заново: **перезапустите бэкенд**. Работающий процесс пересоздание тома
не заметит и будет ходить в пустую базу с ошибками вида
`relation "projects" does not exist`. Если перезапускать не хочется, схему можно
накатить отдельно — `alembic upgrade head` из каталога `backend`.

Своя миграция нужна, когда поменялись модели. Postgres при этом должен быть поднят:
autogenerate сравнивает модели с живой базой. Все команды — из каталога `backend`.

Сгенерировать ревизию по изменениям в моделях:

```bash
.venv\Scripts\alembic revision --autogenerate -m "короткое описание"
```

Дальше **обязательно прочитать полученный файл** в `alembic/versions/`. Autogenerate
не распознаёт переименования: колонку `foo` → `bar` он превратит в drop + add,
то есть в тихую потерю данных. Такие места переписываются руками через
`op.alter_column(..., new_column_name=...)`. Заодно стоит проверить, что в миграцию
не утекло лишнее — например, индексы, созданные вручную мимо моделей.

Применить:

```bash
.venv\Scripts\alembic upgrade head
```

Посмотреть SQL, ничего не применяя (полезно перед накатом на живую базу):

```bash
.venv\Scripts\alembic upgrade head --sql
```

Ещё: `alembic current` — на какой ревизии база сейчас, `alembic history` — вся цепочка,
`alembic downgrade -1` — откат на шаг назад. URL базы alembic берёт из настроек
приложения (`.env` в корне репозитория), в `alembic.ini` он намеренно не задаётся,
поэтому команды работают из любого каталога с активным venv.

Neo4j и Qdrant миграций не требуют: граф пересобирается индексацией, а коллекция
векторов создаётся сама и пересоздаётся при смене размерности эмбеддингов.
