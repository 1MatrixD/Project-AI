# Скороход API

Backend доставки еды по городу: заказ из ресторана, расчёт доставки, подбор курьера,
трекинг и приём платёжных вебхуков.

Веб-фронт живёт в отдельном репозитории `skorohod-web` (Next.js, порт 3020),
мобильное приложение — в `skorohod-mobile`.

## Стек

- Python 3.11+
- FastAPI + Uvicorn
- SQLAlchemy 2.0 (typed ORM) + Alembic
- PostgreSQL 15
- httpx — клиент платёжного провайдера
- python-jose — JWT

## Запуск

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # заполнить руками, секреты — в 1Password
alembic upgrade head
uvicorn app.main:app --reload --port 8020
```

Прод крутится за nginx, воркеры (`app/workers/*`) стартуют внутри процесса приложения
в `lifespan`, отдельного celery нет и не планируется.

## Домен

**Заказ.** Пользователь собирает корзину из позиций одного ресторана, указывает адрес
из своего профиля и (опционально) промокод. Все деньги в системе — **копейки, `int`,
поля с суффиксом `_kop`**. Округление только в одном месте — `app/utils/money.py`.

Статусы заказа: `created → paid → cooking → courier_assigned → at_restaurant →
picked_up → delivering → delivered`, плюс терминальные `cancelled` и `refunded`.
Переходы описаны в `app/services/statuses.py`, менять статус напрямую (`order.status = ...`)
нельзя — только через `set_status()`, иначе не запишется история и не уйдёт пуш.

**Зоны.** Город нарезан на зоны доставки. Зона — это полигон (`[[lat, lon], ...]`) плюс
предрассчитанный bbox, который используется как быстрый префильтр перед точной проверкой
вхождения точки в полигон.

**Промокоды.** Виды: `percent` и `fixed`. У промокода есть минимальная сумма заказа
(`min_total_kop`), окно активности и лимиты — общий (`total_limit`) и на пользователя
(`per_user_limit`). Факт применения фиксируется строкой в `promo_usage`, по ней же
считаются лимиты.

**Смены курьеров.** Курьер открывает смену на конкретной зоне, закрывает в конце дня.
День смены — **московский** (см. `app/utils/timeutil.py::local_day`), потому что смена,
начатая в 23:30, должна попасть в тот же день, что и её основная часть.

**Вебхуки.** Платёжный провайдер шлёт события `payment.succeeded`, `payment.failed`,
`refund.succeeded`. Провайдер **гарантирует доставку, но не гарантирует однократность**:
при таймауте он ретраит событие с тем же `event_id`, поэтому обработка вебхуков
идемпотентна — см. `app/utils/idempotency.py`.

## Назначение курьера

Логика в `app/services/dispatch.py`.

1. Берём заказ в статусе `paid` без курьера (фоновый цикл `workers/assign_loop.py`).
2. По координатам адреса доставки определяем зону: точка проверяется на вхождение
   **в полигон зоны** (ray casting, `zones.point_in_polygon`); bbox используется
   только как дешёвый префильтр, финальное решение принимает полигон.
3. Из курьеров, у которых открыта смена на этой зоне и нет активной доставки,
   выбираем **ближайшего к ресторану** — расстояние считается по `zones.haversine_m`.
4. Если подходящих курьеров нет, заказ остаётся в очереди и цикл вернётся к нему
   на следующей итерации.

## Legacy

`POST /api/v1/checkout` — старый чекаут для мобильного приложения версий < 3.0.
Отдаёт ответ в старом формате (рубли строкой, поле `state` вместо `status`).
Новый код должен использовать `POST /api/v2/orders`.
**Выпилить после релиза 4.2**, когда доля старых клиентов упадёт ниже 1%.

## Соглашения команды

- Деньги — только `int` в копейках, никаких `float` в моделях и схемах.
- Время в БД — UTC (`timestamptz`), в отчётах и сменах — московское.
- Русские докстринги, комментарии — по делу.
- Логи структурные, `logger.info("order.paid", extra={"order_id": ...})`.
