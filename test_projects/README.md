# Тестовые проекты

Две вымышленные кодовые базы — полигон для проверки того, **как система описывает задачи**.
Идея: задача формулируется так же криво, как её приносят с созвона («промик не работает»),
а система должна сама сходить в код, найти настоящую причину и написать нормальное описание
с путями к файлам и планом. Правильные ответы известны заранее и лежат в
[ANSWERS.md](ANSWERS.md) — **это спойлер, не открывай до прогона**.

| | Что это | Стек | Файлов | Зачем |
|---|---|---|---|---|
| [skorohod](skorohod) | «Скороход» — доставка еды курьерами | FastAPI + Next.js | ~50 | **мультирепо**: бэкенд и веб — два отдельных каталога |
| [rentkit](rentkit) | «RentKit» — прокат фото/видеотехники | TypeScript-монорепо (npm workspaces) | ~40 | монорепо: общий пакет правил, API и веб в одном каталоге |

Это фикстура: код написан, чтобы его читали. Но он связный — импорты сходятся,
эндпоинты бэкенда совпадают с теми, что зовёт фронт, доменные термины общие,
и оба стенда поднимаются в docker.

## Посмотреть, что за сервисы

У каждого проекта свой compose: база со схемой и демо-данными, API и витрина.
Порты разведены с основным стендом «Проектов ИИ» (5432 / 8010 / 3010), так что
можно держать всё поднятым одновременно.

```bash
docker compose -f test_projects/skorohod/docker-compose.yml up -d --build
```

```bash
docker compose -f test_projects/rentkit/docker-compose.yml up -d --build
```

| | API | Витрина | Postgres |
|---|---|---|---|
| Скороход | http://localhost:8020/docs | http://localhost:3020 | 5442 |
| RentKit | http://localhost:8030/api/health | http://localhost:5173 | 5443 |

Быстрее всего состав сервисов виден в Swagger «Скорохода» (`/docs`): там все ручки
с описаниями — два чекаута (v2 и legacy v1 для мобилки), смены курьеров, зоны, промо,
вебхук платежей, SSE-трекинг. У RentKit Swagger нет, ручки перечислены в
[rentkit/README.md](rentkit/README.md), каталог удобно посмотреть запросом
`GET /api/items`.

Демо-данные осмысленные: у «Скорохода» два ресторана с меню, три курьера на сменах,
три зоны доставки и пара заказов (включая ночной — на нём и видно расхождение
в суточном отчёте); у RentKit десять единиц техники, три клиента и три брони
в разных статусах.

Снести вместе с базами: `docker compose -f … down -v`.

Это стенд «посмотреть и потыкать», а не рабочее приложение: платёжный провайдер —
внешний URL-заглушка, часть ручек за JWT, сценарии до конца не проходятся.
Для проверки описания задач это не нужно — система читает код, а не запускает его.

## Как загрузить

### Скороход (два каталога)

1. Создать проект, каталог: `…\test_projects\skorohod\skorohod-api`
2. Дождаться индексации, затем на вкладке «Обзор» → меню «⋯» → **«🗂 Добавить каталог»** →
   `…\test_projects\skorohod\skorohod-web`
3. Файлы веба появятся с префиксом `skorohod-web/`, индекс обновится сам.

Так проверяются сразу две вещи: мультирепо как таковое и то, догадается ли ИИ,
что причина бага лежит в другом корне (задачи №1 и №4 — межрепные).

### RentKit (один каталог)

Создать проект с каталогом `…\test_projects\rentkit` — внутри `packages/core`, `apps/api`, `apps/web`.

## Что проверяем

**Главное — качество описания задач.** Берём формулировки из [TASKS.md](TASKS.md),
заводим их в канбан как есть (заголовок + пара строк) и жмём **«🧠 Проработать»**
(или «Проработать новые (RLM)» на доске). Смотрим, что получилось:

- нашла ли система **настоящую** причину, а не первую похожую строчку;
- перечислены ли конкретные файлы (и правильные ли);
- есть ли в плане шаги диагностики и проверки, а не «поправить логику»;
- заметила ли, что README проекта врёт (в обеих базах документация описывает
  желаемое поведение, а код делает иначе);
- для задач-фич — вменяемая ли декомпозиция по кнопке «Декомпозировать».

Заодно можно погонять:

- **гибридный поиск** — запросы не словами из кода: «почему списывают дважды»,
  «кто выбирает курьера», «откуда берётся скидка за неделю»;
- **чат/RLM** — «как устроен расчёт доставки», «что произойдёт, если провайдер
  пришлёт вебхук дважды»;
- **ИИ-проверку выполненности** — задачи-фичи заведомо не сделаны, система не должна
  их закрывать;
- **соглашения (Decisions)** — например «деньги везде в копейках» и посмотреть,
  всплывает ли это в проработке.

## Оценка

В [ANSWERS.md](ANSWERS.md) на каждую задачу: настоящая причина, файлы, которые
обязаны попасть в описание, как выглядит хороший план и типичные ложные версии
(куда ИИ, скорее всего, свернёт, если не читал код).

Файл лежит **вне** каталогов проектов, поэтому в индекс не попадёт — но и не клади
его внутрь `skorohod/` или `rentkit/`.
